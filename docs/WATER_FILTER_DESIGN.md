# 智能去水 — 设计说明

面向「长帖里全是 mark / 插眼这类没信息的回复，我想只看有内容的楼层」这一需求：
在帖子页「更多」菜单里点「智能去水」，应用逐页抓完全帖、按**本地规则**剔掉灌水楼层，
再生成一份新的本地帖子（去水版），与原帖的离线存档在「保存的帖子」里**并列**存在。

判定**不调用任何模型**：即时、不耗额度、结果可预期（同一帖同一规则跑两次结果相同）。

可选加分项：确认框里可以点「按本帖主题生成」，让 AI 看标题与主楼列出这帖特有的灌水
表达（如追更帖的「催更」）。那组规则**只对本次任务生效、不落盘**（§3.6），
判定本体与它无关——AI 未配置时去水照常可用。

## 1. 口径（产品语义）

| 项 | 取值 | 说明 |
|---|---|---|
| 判定方式 | **本地规则** | 不调模型；AI 未配置也照常可用 |
| 规则来源 | 内置词表 + 用户自定义（持久）+ AI 生成（**仅本次**） | 三者的并集；AI 只是**追加**可选规则，不替换本地判定（§3.6） |
| 抓取范围 | **全帖不限页数** | 帖子有多少页就抓多少页；不做 AI 全帖总结那种「20 页上限 + 头尾取样」 |
| 严格程度 | 2 档预置 + 用户自定义规则 | 默认「只清纯灌水」；可切「加强去水」；自定义规则任何档位下都生效 |
| 产出 | 一份**独立**存档 | `archiveId = tid + '-w'`，`derivedFrom = tid`；与原帖存档共用 `tid` 但互不覆盖 |
| 产出位置 | **我的 → 收藏、保存与跟踪帖子 → 保存的帖子** | 与原帖的「离线保存」并列，带「去水」标签；不联网也能读。入口对话框内必须明示（§6.1） |
| 与原帖的关系 | 并列，不修改原帖 | 去水版删除**不影响**原帖存档，反之亦然 |
| 重复去水 | 覆盖上一份去水版 | 同一帖反复去水只留最新一份，列表不会长草 |
| 覆盖范围如实汇报 | 是 | 安全阀触顶 / 有页抓失败 / 有页跳过，都写进结果文案 |
| 判定失败方向 | **宁漏不误删** | 任何「疑似但不确凿」的楼层一律保留（见 §3） |

## 2. 判定顺序（三期过滤）

一期不过才进下一期。顺序不可换：豁免必须最先，自定义规则必须最后（用户显式配置
优先于预设，但硬豁免仍然最优先）。

| 期 | 内容 | 命中后的动作 |
|---|---|---|
| 0. 引用剥离 | 先把 `[quote]…[/quote]` 整段剥掉，判定只看作者自己写的内容（§2.2） | 不判水，只缩小判定范围 |
| 1. 硬豁免 | 主楼（`lou=0`）／带附件／带楼中楼或热评／正文（引用之外）含富内容标记 | **保留**，不再进入后续判定 |
| 2. 等级内置词表 | 按严格等级取用（见 §3） | 判水 |
| 3. 自定义规则 | `包含` / `完全等于` / `字数不超过`；用户持久的 + AI 本次生成的（§3.5 / §3.6） | 判水 |

### 2.1 硬豁免的富内容标记

`[tid=` `[pid=` `[uid=` `[img` `[attach` `[url` `[code` `[table` `[list` `[*]`
`[media` `[video` `[flash` `[collapse` `[album` `[sound` `[sup` `[sub` `[sp` `[h]` `[hr]`

- **一律用开标记匹配**，且多数不写收尾的 `]`：
  NGA 的图片/媒体/折叠标签普遍带参数（`[img=100,100]`、`[collapse=标题]`），
  写死 `[img]` 会漏判；闭合标记还可能出现在被裁掉前半段的引用里。
- 这些标记代表图片、代码、表格、外链，即「有信息量」，**无论正文多短都不判水**。
- **刻意不含 `[quote`**：引用块在进判定前已被剥掉（§2.2）。别人帖子里的图片与外链
  不该让本层免于判水——否则「引用一整楼 + 一个 mark」永远不会被清。

### 2.2 引用块整段剥离（`stripQuoteBlocks`）

「引用别人的回复」在 NGA 里是很常见的形态：`[quote][pid=…]…[/pid]别人的话[/quote]` +
作者自己的一句短评。判定前先做这一步，有三条语义：

1. **引用不计入长度**：`长度不超过` 规则量的是作者自己写的字数。若把引用正文算进去，
   一条「引用长文 + 顶」的楼层永远凑得够字数、永远躲过长度规则。
2. **引用里的富内容也不豁免**：见 §2.1 末条。
3. **引用不给楼层任何豁免**：只带引用、自己一个字没写的楼层**保留**——它是作者刻意
   带出的上下文，不是灌水；但「引用 + mark」这种自写部分仍是水，照删。

实现要点：

- **支持嵌套引用**：从每个开标记起按深度配对闭标记，整段（含嵌套）一起丢。
- 两类异常形状按「自该开标记起直到文末都算引用」处理，理由都是**宁可少判一层水，
  也不要把别人的话当作者的正文**：开标记本身被截断（找不到 `]`）、没有配对的 `[/quote]`。
- 只有**孤立闭标记**（开标记被裁掉）不处理：这种情况下引用正文会留在文本里，使长度
  偏长、判定偏保守——方向是安全的，不值得为它去猜边界。

## 3. 内置词表（等级口径）

### 3.1 BASIC「只清纯灌水」（默认）

| 规则 | 判据 | 原因文案 |
|---|---|---|
| 空文本 | 剥标记后为空 | 纯表情或纯标记 |
| 纯标点 | 不含任何「信息字符」（见 §3.3） | 纯标点符号 |
| 重复字符 | 整条由同一字符重复构成（`。。。`／`!!!!`／`aaa`） | 重复字符灌水 |
| 纯数字 | 整条半角数字且长度 ≤ 10 | 纯数字回复 |
| 标记类 | **整条等于**词表项（或只多一个尾部语气符） | 标记类回复 |

标记类词表（`MARK_TOKENS`）：`mark` `mk` `ma` `make` `马克` `马克一下` `马克一记`
`马克吐温` `mark一下` `留名` `留个名` `留个脚印` `留爪` `插眼` `插个眼` `眼` `标记`
`标记一下` `记号` `作个记号` `收藏` `收藏了` `先收藏` `绑定` `绑` `前排` `沙发` `板凳`
`地板` `地下室` `占楼` `占位` `路过` `飘过` `打酱油` `顶` `帮顶` `顶一下` `up` `upup`
`看看` `看一下` `好` `很好` `不错` `收了` `拿走`

**必须整条等值，不能包含匹配**：这些词多数是常用字（`眼`／`顶`／`好`），包含匹配会
误伤「顶楼的图挂了」这类正常回复。代价是「mark 一下，谢谢楼主」漏删——它带语气、
可能有人味，交给 AGGRESSIVE 档更合适。

尾部语气符容忍（`TAIL_CHARS`）：`了~!！。的呀啊`，即 `mark了`／`插眼~`／`马克!` 也命中。
**只放宽一个字符**：放宽越多，误伤正常短句的概率越高。

### 3.2 AGGRESSIVE「加强去水」

在 BASIC 全部规则之上追加：

| 规则 | 判据 | 原因文案 |
|---|---|---|
| 纯笑声 | 整条只由 `哈嘿嘻呵~` 构成 | 纯笑声 |
| 简短闲聊 | 长度 ≤ 12 且**包含**词表任一项 | 简短闲聊 |

短闲聊词表（`SMALL_TALK_TOKENS`）：`谢谢分享` `感谢分享` `多谢分享` `谢谢楼主`
`感谢楼主` `谢谢` `多谢` `感谢` `辛苦了` `支持` `支持一下` `好帖` `好贴` `好文` `厉害`
`牛` `牛逼` `牛b` `nb` `太强了` `强贴` `哈哈哈哈` `哈哈` `笑死` `笑死我了` `呵呵` `同求`
`求资源` `求链接` `求地址` `同上` `同问` `同感` `学习` `学习了` `受教` `受教了` `关注`
`围观` `涨知识` `涨姿势` `有道理` `确实` `确实如此` `同意` `赞同` `附议` `打卡` `签到`
`真实` `有趣` `有意思` `第一个`

**长度上限 12 是这里的关键约束**：它把「感谢分享」判水，但保留
「感谢分享，不过第 3 张图的参数好像写反了」这类带实质内容的回复。

### 3.3 「信息字符」用反向白名单

判「纯标点/纯符号/纯表情」时，**只把枚举到的符号码点判为无信息**，其余一律视为有信息：

- emoji 序列组成部分（零宽连接符 `U+200D`、变体选择符 `U+FE0F`、键帽 `U+20E3`）
- ASCII 标点四段、通用标点 `U+2000–206F`、货币符号、箭头、杂项技术符号、
  带圈数字、制表符、几何图形、`U+2600–27BF`、`U+2B00–2BFF`
- CJK 符号与标点 `U+3000–303F`、CJK 兼容形式 `U+FE30–FE4F`、全角标点四段
- emoji 补充平面 `U+1F000–1FAFF`

**为什么必须反向**：正向白名单（"只保留汉字/字母/数字"）会把泰文、西里尔文、
阿拉伯文、各类扩展汉字这些**没被枚举到的文字**误判成纯标点，一删就是整段内容。
反向白名单的代价是「未知符号」被当成有信息（漏删几个纯符号楼），对破坏性操作来说
这个方向的错误才是可接受的。

### 3.4 判定对象是「剥标记后的紧凑文本」

原始正文混着标签与表情码，直接做长度/包含判断会把 `[b]mark[/b]` 算长、把 `[s:1]`
当成内容。因此进判定前依次做三步（顺序不可换）：

1. `stripQuoteBlocks`：整段剥掉引用块（§2.2）。**必须在剥标记之前**——否则引用块里
   的 `[quote]` 已被 `stripMarkup` 吃掉，就再也认不出引用边界了。
2. `stripMarkup`：把**短标签**（不含换行、长度 ≤ 32）剥掉。正文里天然出现的方括号
   （长引用、含换行的中括号）保持原样，避免把正常内容吃掉之后误判为「纯标点」。
3. `compactText`：移除所有空白（含全角空格 `U+3000`）。

长度阈值、短闲聊上限、包含/等值匹配**全部基于第 3 步的结果**——即作者自己写的、
不含引用的紧凑文本。

`__GROUPS` / 附件 / 楼中楼等语义字段来自**解析后的 `PostInfo`**，不靠正文文本猜。

### 3.5 自定义规则

| 类型 | 语义 | 校验 |
|---|---|---|
| `contain`（内容包含） | 紧凑文本包含该关键词 | 非空 |
| `equals`（内容完全等于） | 归一化（去空白 + 转小写）后完全相等 | 非空 |
| `max-length`（字数不超过） | 紧凑文本长度 ≤ 上限，**单位为「字」** | 1–500 的十进制整数 |

- **长度类规则必须带单位「字」**：不写单位，用户会按字节或字符理解（汉字与 emoji
  的计数完全不同），阈值就填不准。类型短名（`waterRuleTypeLabel`）与完整描述
  （`waterRuleTypeDetail`）两处都要带。
- **长度不含引用**：量的是作者自写部分（§2.2 第 1 条）。
- **多条长度规则取最宽松的一条**：同时配 5 与 10 时，用户意图是「10 以内都算水」。
- 未启用的规则不参与判定。
- 任何等级下都生效，且与等级词表**取并集**（命中任一即判水）。

### 3.6 AI 追加的规则（可选，只对本次任务生效）

内置词表与用户自定义规则都是**字符匹配**：前者只覆盖全站通用的灌水词（mark / 插眼），
后者要用户自己想出关键词。而每个帖子有自己的「水法」——追更帖满屏「催更」、资源帖
满屏「求个网盘」、攻略帖满屏「学到了」——这些词固定词表盖不到，用户手写又得先读完整帖。
因此对话框里提供「按本帖主题生成」，让模型看一眼标题与主楼，列出这帖特有的灌水表达。

**产品前提不变**：这是**追加**一个可选来源，不是替换本地判定。判定仍然不调模型，
AI 未配置时照常可用（按钮会以 `getActiveAiValidationMessage()` 的文案提示原因）。

#### 3.6.1 只用于本次，绝不落盘

AI 规则按**这一帖的主题**生成，写进全局自定义规则会在别的帖子上乱删（「催更」在小说帖
里合理，在技术帖里就是误伤）。因此：

- 规则由 `WaterFilterContent` 通过 `onAiStateChange` 回传给 `ThreadPanel`，存在页内
  字段里，**不写入设置**；
- 发起任务时与持久化的自定义规则**合并**后传给服务（`startWaterFilter`）；
- 每次打开对话框都把页内字段清空——对话框是新建实例，页内字段不重置就会把上一个帖子的
  规则静默带进这一次去水；
- UI 上必须明说「AI 规则只用于本次去水，不会写入你的自定义规则」。

#### 3.6.2 提示词契约（`AiScenario.WATER_RULE_GEN`）

- 场景已注册进 `model/AiScenarioConfig.ets`：有元数据、默认 system prompt、
  注入字段说明，因此 AI 设置页里能独立编辑它的 prompt（`AiSettingsPanel` 的
  `ScenarioCard` + `icon_ai_water_rules`）。
- 注入数据只有两项：**帖子标题** + **主楼正文纯文本**（截断到 1200 字）。
  只看标题太薄，看整帖浪费额度与上下文。
- 主楼不在当前分页窗口时 `ThreadPanel.resolveOpPlainText()` 返回空串，此时 AI 只看标题
  ——比不生成规则更保守，不会因此失败。
- 输出约定为固定 JSON：`{"rules":[{"type":"contain","value":"示例词"}, …]}`，
  `type` ∈ `contain` / `equals` / `max-length`，最多 12 条。
- Prompt 里显式要求**不要写通用灌水词**（已由内置词表覆盖）与**严禁单字 contain**
  （「图」「求」「问」「顶」「好」会命中大量正经回复），并要求针对「引用 + 短评」的
  楼层用 `contain` 而不是 `max-length`。

#### 3.6.3 AI 输出是不可信输入（防御性解析）

`parseWaterRules` 是纯函数，逐条防御、**不抛异常**，任何一条坏数据都不影响其余条目：

| 防御 | 处理 |
|---|---|
| 回复裹 ```json 代码块或前后带解释 | 定位第一个 `{` 到最后一个 `}` 截出 JSON 子串，再 `JSON.parse` |
| 缺失 / 非字符串字段 | `readString` 归一，空值转空串 |
| 类型非法 | 丢弃该条 |
| 值非法（空、长度规则非 1–500 整数） | 复用 `validateWaterRule`，不通过则丢弃 |
| **单字 contain** | 丢弃（`MIN_CONTAINS_LENGTH = 2`）——单字规则是破坏性的 |
| 关键词带引号 / 空白 | 剥包裹引号 + `compactText`（判定比对的是紧凑文本，带空格的规则永远匹配不上） |
| 重复项 | 按 `type + ':' + value` 去重 |
| 条数超限 | 截到 `MAX_AI_RULES = 12` |

#### 3.6.4 调用路径与交互

- 复用**唯一** AI 通道 `chatCompleteWithActiveAiStream`，不展示流式增量（一次性取结果），
  不得为它另开 HTTP 路径。
- 取消令牌在对话框 `aboutToDisappear` 里 `cancel()`：不中断会留下无人接收的回调。
- **生成中点「开始」必须被拦住**（`waterFilterAiGenerating` 门禁）：规则还没拿到就开始
  抓取，用户以为用了 AI 规则、实际一条都没用上，比不用 AI 更糟。
- 生成失败或解析为空都不阻断去水：失败在 AI 区块内显示原因，解析为空时如实写
  「AI 认为这个帖子没有需要额外过滤的表达」。

## 4. 存储模型：与离线存档并列

| | 离线保存 | 智能去水 |
|---|---|---|
| `archiveId` | `tid` | `tid + '-w'`（`DERIVED_ARCHIVE_SUFFIX`） |
| `derivedFrom` | `''` | `tid` |
| `subject` | 原帖标题 | 原帖标题 + `（去水版）` |
| 落盘位置 | `filesDir/saved_threads/<archiveId>.json` | 同左 |
| 列表标记 | 无 | 「去水」描边标签 |

- 存档的**唯一键是 `archiveId` 而不是 `tid`**（`SavedThreadStore.isValidArchiveId` 的
  正则是 `^[0-9]{1,16}(-w)?$`，拒绝越界与非法后缀）。这是「同一主题并存两份存档」的基础。
- `SavedThreadStore.getByTid(tid)` 内部走 `getByArchiveId(baseArchiveIdOf(tid))`，
  存量调用点与旧书签无需改动；`hasDerivedArchive(tid)` 供入口做「已有去水版」判断。
- 路由用 `Screen.savedThread(archiveId, tid, page)`，`ThreadPanel.archiveId` 透传，
  离线分支按 `getArchiveId()`（空串回退 `tid`）取档。
- 「保存的帖子」列表的键、删除、打开全部按 `archiveId`，`ForEach` 键也是 `archiveId`。
- **去水版不再支持再次去水**：`ThreadSource.SAVED` 下菜单只渲染「在线模式打开」，
  去水入口本身不在存档分支出现（§6）。

## 5. 全帖抓取（上千页帖子的工程约束）

| 约束 | 取值 | 说明 |
|---|---|---|
| 页间节流 | 250 ms（`PAGE_FETCH_INTERVAL_MS`） | 对 NGA 保持礼貌，避免触发风控 |
| 总页数来源 | 服务**自行探测** | 请求末页（`page=e`）读 `__ROWS` / `__R__ROWS_PAGE` 换算 |
| 单页失败 | 只跳过该页并计数 | 上千页里偶发失败是常态，不得中断整帖 |
| 重复楼 | 按 `pid` 去重 | 相邻页偶有重复的尾楼，去水版里同楼不能出现两次 |
| 安全阀 | 8000 层 / 800 万字符 | 触顶立即停止扫描并落盘，如实说明「仅覆盖前 N 页」 |
| 产出分页 | 每页 20 楼（`ROWS_PER_PAGE`） | 与 NGA 在线排版一致 |
| 后台继续 | dataTransfer 长时任务 | 申请不到时在进度提示里如实告知「请保持应用在前台」 |

### 5.1 为什么总页数必须自己探测

调用方（`ThreadPanel`）手里的 `mgr.totalPages` 在「只看楼主」等**服务端筛选态**下是
筛选后的页数，用它决定抓取范围会漏抓大半个帖子；单帖兜底响应里的页数更不可信。
因此 `run()` 先 `probeTotalPages(token, tid)`，探测失败才回退到入参
`hintTotalPages`——**不因为一次探测失败就整个任务作废**。

### 5.2 重组：保留原始行，合成同形状页

- 判定的输入是解析后的 `PostInfo`（有 `lou` / `attachs` / `comments` 等语义字段），
  但保留时把该行 **raw row 原样**放进新页：图片、楼中楼、热评、投票全都不动，
  去水版与原帖走**完全相同**的渲染管线，也不会因字段裁剪而丢内容。
- 合成页形状与在线响应一致（`data.__R` / `__U` / `__F` / `__T` / `__ROWS` /
  `__R__ROWS_PAGE` / `__PAGE`），因此打开时统一由 `fillThreadResult` 解释。
- `__ROWS` 报「**全帖保留楼层总数**」而非本页行数：与在线响应的语义一致（每页都
  报告主题总行数），也让 `parseThreadData` 推出的总页数与实际页数吻合。
- **`__U` 必须按页裁剪**：只带本页楼层引用到的作者条目。`__U` 若不裁剪地复制到
  每一页，1000 页的存档光作者表就会膨胀到上百 MB。
- 承载 `__GROUPS`（用户组名 → 组名映射）的那一条**每页都带上**：`fillThreadResult`
  取第一个带 `__GROUPS` 的条目建映射，不带的话除首页外的楼层会退化成数字组 ID。
- **内存策略：不累积整页 raw**。每页解析后立即判定，只留下通过的原始行，其余
  （含该页的大 `__U` 表）当场变成垃圾。

### 5.3 黑名单与关键词屏蔽不参与取舍

判定时传空黑名单/空关键词（与离线保存同口径）：屏蔽是**阅读时**的用户偏好，
不该让存档内容随之变化——否则同一帖两个人保存出来的去水版层数不同。

## 6. UI 入口

### 6.1 帖子页「更多」菜单 →「智能去水」

- 与「收藏夹」「离线保存帖子」「AI 总结帖子」「跟踪帖子更新」并列的**帖子级动作**，
  只出现在非离线存档分支。
- 入口弹官方 `CustomContentDialog`（`WaterFilterContent`），四件必读信息：
  **要抓多少页**、**预计耗时（标注「估算」）**、**当前严格等级与生效规则条数**、
  **产出物存到哪儿**。
- **产出位置必须写在框里**（`SAVE_LOCATION_HINT`）：用户点完「开始」就离开对话框了，
  不提前说就找不到产出物——去水版不是回帖、不会出现在帖子页，只在「保存的帖子」列表里。
  文案用完整路径（我的 → 收藏、保存与跟踪帖子 → 保存的帖子）并说明「与原帖离线保存并排、
  不联网也能读」。
- 框内还有 **AI 规则区块**（`WaterFilterContent.aiSection`）：按本帖主题生成 / 重新生成、
  生成中的说明、已生成规则的清单，以及「只用于本次去水、不写入自定义规则」的声明；
  生成中点「开始」被拦（§3.6.4）。
- 对话框里的等级选择**直接写回设置**（`setWaterFilterLevel`），不在框内另存一份：
  改了等级却没点「开始」就会以为已经生效，那是最容易踩的误解。
- 页数 > 50 时用 `AppColors.warning` 单独提示「该帖较长，预计耗时 X」并说明任务在
  后台继续、随时可取消。
- 内容整体包在 `Scroll` 且 `constraintSize({ maxHeight: 400 })`：对话框自身不滚动，
  AI 规则清单会把内容撑长，超出的部分会被静默裁掉。

### 6.2 全局进度指示器

挂在 `MainPage` 的 `WaterFilterProgressIndicator`（与 `SavedThreadProgressIndicator`
同一模式）：

- 轮询 `waterFilterProgress` 发布器状态，底部胶囊显示进度条 / 标题 / 页数与已去层数 /
  剩余时间，并提供**取消**入口（调 `threadWaterFilterService.cancel()`）。
- 定位在 `WATER_FILTER_PROGRESS_BOTTOM_MARGIN = 192`：比 TTS 胶囊（148）再高一档，
  两条任务并行时不重叠。
- **为什么这里做全局发布**（而 AI 全帖总结用页内浮层）：去水可跑几十分钟，用户一定
  会离开帖子页去干别的，进度必须跨页可见。

### 6.3 设置 →「去水规则」（`WaterFilterRulesPanel`）

与「关键词屏蔽」同层级的一块全局配置：

- **严格等级**二选一，点即生效并落盘（单选语义自洽，不加「保存」按钮）。
- **自定义规则**增删改 + 启用开关；编辑器是类型三选一（包含 / 完全等于 / **字数不超过**）
  + 文本输入，实时校验（`validateWaterRule`），失败以 Toast 报因。
- 类型选择就用「字数不超过」，输入框 placeholder 写「不超过多少字（1~500）」，下方
  一句话说明写清「引用的内容不计入长度」——单位与口径都是用户在填之前必须知道的。
- 二次确认只有两处：「删除单条」与「清空全部」。
- 设置页入口显示当前等级角标（有自定义规则时补上条数）。角标靠
  `AppStorage` 的 `waterFilterVersion` 驱动——规则页与设置页是路由栈里并存的
  两个 Screen，从规则页返回时设置页**不会重建**，只靠 `aboutToAppear` 会停在旧值。
- 页底「判定顺序」说明与引擎保持一致（四步，含引用剥离那一步）：说明文案与判定口径
  不一致，会让用户按错误的模型理解结果。

## 8. 已知故障模式

| 现象 | 根因 | 正确处理 | 禁止的补丁 |
|---|---|---|---|
| 去水版楼层数比预期多（该删的没删） | 用了正向白名单判「信息字符」，未枚举文字被算成有信息量 | 反向白名单（§3.3）是刻意取舍，宁漏不误删 | 为了"删得更干净"改成包含匹配标记词 |
| 正常回复被误删 | 标记词表用了包含匹配 | 整条等值 + 只容忍一个尾部语气符 | 把 `顶`/`好`/`眼` 从词表里删掉后改用长度阈值（会误伤短的正经回复） |
| 「引用 + 一个 mark」的楼层删不掉 | 富内容标记表里含 `[quote`，整层被豁免 | 引用块先进 `stripQuoteBlocks` 剥掉，豁免只看自写部分（§2.2） | 把 `[quote` 从豁免表删掉却让引用正文继续参与判定（长度被别人的话凑够） |
| 「引用长文 + 一句短评」躲过长度规则 | 引用正文被算进了「字数不超过」 | 引用剥离在量长度之前（§2.2 / §3.4） | 把长度阈值调大（治不了根，还会误伤短的正经回复） |
| 去水版打开后除首页外楼层显示数字用户组 ID | 合成页没带 `__GROUPS` 载体 | 每页都带上用户组载体那一条（§5.2） | 每页复制整张 `__U`（存档膨胀百 MB） |
| 1000 页帖子的存档在手机上 OOM | 累积了整页 raw 或每页复制 `__U` | 每页判定完只留通过的原始行；`__U` 按页裁剪 | 先把整帖 raw 攒起来再一次组装 |
| 抓取范围比帖子实际页数少 | 用调用方（「只看楼主」筛选态）的页数当抓取范围 | 服务自行 `probeTotalPages` | 增加"经验页数系数" |
| 去水版与原帖存档相互覆盖 | 两者共用 `tid` 作唯一键 | 唯一键是 `archiveId`（原帖 = tid，去水版 = tid + '-w'） | 把去水版另存到其它目录（打开路径会分叉） |
| 从规则页返回设置页后角标还是旧等级 | 两个 Screen 并存，设置页不重建，`aboutToAppear` 不再触发 | 依赖 `waterFilterVersion`（`@StorageProp` + `@Watch`） | 在 `onPageShow` 里刷新（ActivityRouter 的 Screen 栈不走 page 生命周期） |
| 加到一半返回/退出，去水版却写进了存档 | 中途的 `isAborted` 判定漏检 | 每页抓取、节流后、落盘前都查 `isAborted(generation)` | 只靠取消标记布尔值（换代后仍会写） |
| AI 规则在别的帖子上乱删 | 把会话级 AI 规则写进了持久化自定义规则 | AI 规则只经 `onAiStateChange` 回传、当次合并，绝不落盘（§3.6.1） | 直接调 `addWaterRule` 落盘（换个帖子就误伤） |
| 上一个帖子的 AI 规则被带进这一次去水 | 页内字段在重开对话框时没清零 | `openWaterFilterDialog` 开头重置 `waterFilterAiRules` / `waterFilterAiGenerating` | 依赖对话框组件自己重置（本页字段才是真源） |
| 生成中点「开始」，用户以为用了 AI 规则 | 没拦生成中的开始 | `waterFilterAiGenerating` 门禁 + Toast | 静默开始（比不用 AI 更糟：结果与用户的预期不符） |
| AI 给出单字规则，大批正常回复被删 | 模型输出不可信，且单字 `contain` 破坏性极强 | `MIN_CONTAINS_LENGTH = 2` 丢弃 + prompt 明令禁止单字 | 放宽到 1 字「交给模型自己判断」 |
| AI 回复裹着 ```json 或带解释文字，一条规则都没解析出 | 用固定前缀匹配 JSON | 定位第一个 `{` 到最后一个 `}` 截子串再 parse（§3.6.3） | 直接 `JSON.parse(全文)`（模型加一句话就整体失败） |
| 对话框里 AI 规则清单被裁掉看不全 | 对话框自身不滚动，内容被撑长 | 内容包 `Scroll` + `constraintSize({ maxHeight: 400 })` | 限制 AI 规则条数（规则条数不是显示问题的根因） |

## 9. 验证要求

### 9.1 自动验证

- API 26 debug HAP 构建通过（`hvigorw assembleHap`）。
- EOL 门禁通过（`node scripts/check-eol.mjs`，仅 `oh-package-lock.json5` 为已知历史违规）。
- BBCode 同步无漂移（`node tools/bbcode-ts/scripts/sync-to-ets.mjs --dry` 报 0 修改）。

### 9.2 设备或模拟器验证

判定：

- 「mark」「插眼」「马克」「留名」「绑定」这类单层回复在默认档被剔除。
- 「mark 一下，谢谢楼主」在默认档**保留**，切到「加强去水」后仍保留（长度超 12），
  但「谢谢分享」「哈哈哈哈」在加强档被剔除。
- `顶楼的图挂了` 这类含 `顶` 但语义正常的回复**不被剔除**。
- 带图片附件 / 带楼中楼 / 主楼的楼层**永不被剔除**。
- **只引用、自己一个字没写的**楼层保留；「引用别人一整楼 + 一个 mark」这类自写部分是水的
  **照删**。
- 引用不计入长度：配一条 `字数不超过 = 20`，录一层「引用 200 字长文 + `顶一下`」——
  该层仍被剔除；只引用不写字的那层不受影响。
- 「😀😀😀」「。。。」「!!!!」「12345」在默认档被剔除。
- 自定义规则三种类型各命中一次；未启用的规则不影响结果；两条长度规则取宽松值。

AI 规则（需先配置 AI；未配置时下列行为应降级为「提示原因且去水照常可用」）：

- 点「按本帖主题生成」后等待期间点「开始」被拦并提示；生成结束后 AI 区块列出规则清单，
  且每条都能对上 `waterRuleTypeDetail` 的写法（长度类带「字」）。
- **AI 规则不落盘**：关掉再打开对话框，AI 规则清单回到空；设置 →「去水规则」的自定义
  规则列表里没有多出任何条目。
- 生成中途取消（点空白 / 取消 / 返回）不留无人接收的回调：不报错、不弹「生成失败」。
- 未配置 AI 时点生成，提示与其它 AI 场景一致的配置原因，且「开始」仍可用（本地判定
  不依赖 AI）。
- 规则清单很长时对话框内容可滚动，末尾的「产出位置」说明仍看得到。

入口与存储：

- 「更多」菜单里的「智能去水」可见，离线存档模式下不出现该项。
- 确认框内能看到**产出位置说明**（「我的 → 收藏、保存与跟踪帖子 → 保存的帖子」）与
  **AI 规则区块**。
- 未登录时提示「请先登录」；已有任务在跑时提示「已有去水任务进行中」。
- 去水完成后「保存的帖子」列表**同时**出现原帖存档与带「去水」标签的去水版，两条
  都能独立打开、独立删除；删掉去水版不影响原帖。
- 对同一帖重复去水，列表里去水版仍只有一条（覆盖而非堆叠）。
- 去水版打开后版式与在线一致：图片、楼中楼、用户组名、楼层号正常；能「在线模式打开」。

长帖与中断：

- 长帖抓取期间进度胶囊显示页数与剩余时间；离开帖子页后进度仍在。
- 点「取消」后任务立即停止，不生成存档；返回键退出页面不产生残留写入。
- 退到后台再回前台，任务继续（长时任务申请成功时）；申请失败时提示文案说明保持前台。
- 抓取过程中断网：失败页被跳过并计数，结果文案写明「N 页未取到」。

## 10. 维护规则

- 改内置词表（`MARK_TOKENS` / `SMALL_TALK_TOKENS` / 阈值）必须同步更新第 3 节，
  并复核「整条等值 vs 包含匹配」的取舍理由是否仍成立。
- 改 `isSymbolCode` 的区段枚举：方向必须**只增不减**（新增符号区段 = 更保守），
  不得为了删得更狠而收窄；收窄会引入「未枚举文字被误删」的破坏性 bug。
- 改自定义规则类型或校验区间：同步 `model/WaterFilterRule.ets` 的
  `validateWaterRule`、设置页编辑器文案与第 3.5 节。长度类的**单位「字」**在
  `waterRuleTypeLabel` / `waterRuleTypeDetail` 两处都要带上。
- 改引用剥离（`stripQuoteBlocks` 的边界规则）：必须复核第 2.2 节的「宁可少判一层水」
  取舍，并确认 §3.4 的先后顺序仍是「先剥引用、再剥标记」。
- 改 AI 规则的**输出格式**（JSON 的字段名 / `type` 取值 / 条数上限）：三处必须同时改——
  默认 system prompt（`AiScenarioConfig`）、解析器（`WaterFilterAiRulesService`）、
  第 3.6.2 / 3.6.3 节。用户可能已自定义过该场景的 prompt，格式不认识时解析器要按
  「没拿到规则」降级，不得抛异常打断去水。
- **不得**把 AI 规则写进持久化设置（`WaterFilterSettings`）：那是按帖子主题生成的会话级
  数据，落盘就会在别的帖子上误伤（§3.6.1）。改 AI 规则入口时同样不得绕过
  `waterFilterAiGenerating` 门禁。
- 改存档键规则（`archiveId` 正则 / 后缀）：必须同时改 `SavedThreadStore`、
  路由 `Screen.savedThread`、「保存的帖子」列表与导出/导入，并验证存量存档仍可读。
- 改安全阀常量（`MAX_KEPT_ROWS` / `MAX_OUTPUT_CHARS`）：同步第 5 节的表与结果文案。
- 改合成页字段：核对 `fillThreadResult` 的读取口径（尤其 `__U` / `__GROUPS` /
  `__ROWS`），并用一份去水版在离线模式下逐页翻完验证。
- 改对话框必读信息（页数 / 耗时 / 等级 / 规则条数 / **产出位置**）：同步第 6.1 节，
  并复核「产出位置」这条**不可删**——用户只有在这一处能知道去水版存到了哪。
- **不得**把去水判定改成调用模型：那会让结果不可预期、消耗额度，并破坏「AI 未配置
  也能用」这条产品前提。AI 只作为**追加**的可选规则来源（§3.6），不进入判定本体。
