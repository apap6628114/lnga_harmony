# 智能去水 — 判定规则与产出口径

面向「长帖里全是 mark / 插眼这类没信息的回复，我只想看有内容的楼层」这一需求：

```text
帖子页「更多」菜单 →「智能去水」→ 确认弹窗（规模 / 耗时 / 口径 / 产出位置）
  → 逐页抓完全帖（不限页数）
  → 按【本地规则】逐楼判定（不调用模型）
  → 保留原始行、重组成与在线响应同形状的页
  → 落盘为一份独立存档（archiveId = tid + '-w'）
  → 「我的 → 收藏、保存与跟踪帖子 → 保存的帖子」里与原帖离线存档并列
```

> **文档定位**：本文是**重实现规格**——只定义「判什么、怎么判、产出什么、边界在哪」，
> 不绑定任何具体实现，也不要求在既有代码上做增量修改。
> AI 提示词（去水规则生成等场景）的全文契约见 [AI_PROMPT_SPEC.md](AI_PROMPT_SPEC.md)；
> 帖子页本身的窗口 / 入口约束见 [THREAD_DESIGN.md](THREAD_DESIGN.md)；
> 收藏与存档的整体模型见 [FAVORITE_DESIGN.md](FAVORITE_DESIGN.md)。
> 第 10 节列出参考实现的实测缺陷，重实现必须避开（不是可选优化）。

## 1. 产品口径

| 项 | 取值 | 说明 |
|---|---|---|
| 判定方式 | **本地规则**（不调模型） | 即时、不耗额度、同一帖同一规则跑两次结果相同；AI 未配置也照常可用 |
| 规则来源 | 内置词表 + 用户自定义（持久） + AI 生成（**仅本次**） | 三者取并集，命中任一即判水 |
| 抓取范围 | **全帖，不限页数** | 不采用「页数上限 + 头尾取样」那套总结口径 |
| 严格程度 | 2 档内置 + 自定义规则 | 默认「只清纯灌水」；可切「加强去水」；自定义规则在任何档位下都生效 |
| 产出 | 一份**独立**存档 | `archiveId = tid + '-w'`、`derivedFrom = tid`、标题加「（去水版）」 |
| 与原帖的关系 | 并列，不修改原帖 | 删除去水版不影响原帖存档，反之亦然 |
| 重复去水 | 覆盖上一份去水版 | 同一帖只保留最新一份，列表不堆叠 |
| 覆盖范围 | 必须如实汇报 | 触顶 / 有页抓失败 / 有页跳过都要写进结果文案 |
| 失败方向 | **宁漏不误删** | 任何「疑似但不确凿」的楼层一律保留 |

**判定对象是楼层，不是帖子**：命中的楼层整行不进入去水版；未命中的楼层按**原始行**
原样保留（图片、楼中楼、热评、投票都不动），因此去水版与原帖走完全相同的渲染管线。

## 2. 判定管线（顺序不可换）

```text
原始正文（BBCode）
  ├─ 0. 剥引用：stripQuoteBlocks —— 只留作者自己写的内容
  ├─ 1. 硬豁免：主楼 / 带附件 / 带楼中楼或热评 / 正文含富内容标记  → 保留
  ├─ 2. 紧凑文本：stripMarkup（剥短标签）→ compactText（去空白）
  ├─ 3. BASIC 内置词表                                            → 判水
  ├─ 4. AGGRESSIVE 内置词表（仅加强档）                            → 判水
  └─ 5. 自定义规则（含本次 AI 追加规则）                           → 判水
```

顺序语义：

- **豁免必须最先**：豁免楼层不再进入任何后续判定（自定义规则也不能删它）。
- **引用剥离必须先于剥标记**：剥标记会把 `[quote]` 当短标签吃掉，之后再也认不出引用边界。
- **自定义规则必须最后**：用户显式配置的意图优先于预设，但硬豁免仍然最优先。

### 2.1 硬豁免（任一命中即保留）

| 判据 | 数据来源 |
|---|---|
| 主楼（楼号 = 0） | 解析后的楼层对象（lou），不靠正文猜 |
| 带附件（图片 / 文件） | 解析后的楼层对象（attachs 非空） |
| 带楼中楼或热评 | 解析后的楼层对象（comments / hotReplies 非空） |
| 正文（引用之外的部分）含富内容标记 | 见 §2.3 |

### 2.2 引用块整段剥离（`stripQuoteBlocks`）

NGA 常见形态是「引用别人的回复 + 自己一句短评」，判定前必须先剥掉引用：

1. **引用不计入长度**：否则「引用长文 + 顶」永远凑得够字数，躲过所有长度类规则。
2. **引用里的富内容不豁免本层**：别人帖子里的图片与外链不该让本层免于判水。
3. **引用不给楼层任何豁免**：只带引用、自己一个字没写的楼层**保留**——那是作者刻意
   带出的上下文，不是灌水；但「引用 + mark」的自写部分照删。

实现语义（重实现必须一致）：

- 支持**嵌套引用**：从每个开标记起按深度配对闭标记，整段（含嵌套）一起丢。
- 两类异常形状按「自该开标记起直到文末都算引用」处理：① 开标记本身被截断（找不到 `]`）；
  ② 没有配对的 `[/quote]`。理由都是宁可少判一层水，也不要把别人的话当成作者的正文。
- **孤立闭标记**（开标记被裁掉）**不处理**：引用正文会留在文本里使长度偏长、判定偏保守，
  方向是安全的，不值得为它猜边界。
- ⚠️ 注意副作用：异常形状把作者自写正文一并丢弃会**缩短**紧凑文本，反而更容易命中
  `max-length` 类规则（见 §10.9）。

### 2.3 富内容标记（`RICH_MARKERS`，开标记匹配）

正文（引用之外的部分）出现任一即视为「有信息量」，无论多短都不判水：

```text
[tid=  [pid=  [uid=  [img  [attach  [url  [code  [table  [list  [*]
[media  [video  [flash  [collapse  [album  [sound  [sup  [sub  [sp  [h]  [hr]
```

- **一律用开标记匹配、多数不写收尾的 `]`**：NGA 的图片 / 媒体 / 折叠标签普遍带参数
  （`[img=100,100]`、`[collapse=标题]`），写死 `[img]` 会漏判；闭合标记还可能出现在
  被裁掉前半段的引用里。
- **刻意不含 `[quote`**：引用块在进判定前已被剥掉（§2.2）。
- 匹配在**剥引用之后、剥标记之前**的文本上做，且大小写不敏感。

### 2.4 标记剥离与紧凑文本

| 步骤 | 语义 |
|---|---|
| `stripMarkup` | 只把**短标签**剥掉：`[` 起、32 个字符内找到 `]`、且内容不含换行。正文里天然出现的方括号（长引用、含换行的中括号）保持原样，避免把正常内容吃掉后误判成「纯标点」 |
| `compactText` | 移除所有空白：半角空格、`\t`、`\n`、`\r`、全角空格 `U+3000` |

**长度阈值、包含 / 等值匹配、以及所有展示的「N 字」都以紧凑文本为准**（即作者自写的、
不含引用与标记的文本）。⚠️ 计数单位必须是**码点**而不是 UTF-16 code unit（见 §10.1）。

## 3. 内置词表与阈值

### 3.1 BASIC「只清纯灌水」（默认档）

按下列顺序判定，命中即返回原因：

| 序 | 规则 | 判据 | 原因文案 |
|---|---|---|---|
| 1 | 空文本 | 紧凑文本为空 | 纯表情或纯标记 |
| 2 | 纯标点 | 不含任何「信息字符」（§4） | 纯标点符号 |
| 3 | 重复字符 | 整条由同一字符重复构成（`。。。` / `!!!!` / `aaa`） | 重复字符灌水 |
| 4 | 纯数字 | 整条半角数字且长度 ≤ 10 | 纯数字回复 |
| 5 | 标记类 | **整条等于**词表项，或只多一个尾部语气符 | 标记类回复 |

标记类词表（`MARK_TOKENS`，整条等值）：

```text
mark  mk  ma  make  马克  马克一下  马克一记  马克吐温  mark一下
留名  留个名  留个脚印  留爪  插眼  插个眼  眼  标记  标记一下
记号  作个记号  收藏  收藏了  先收藏  绑定  绑  前排  沙发
板凳  地板  地下室  占楼  占位  路过  飘过  打酱油  顶  帮顶
顶一下  up  upup  看看  看一下  好  很好  不错  收了  拿走
```

- **必须整条等值，不能包含匹配**：这些词多数是常用字（`眼` / `顶` / `好`），包含匹配会
  误伤「顶楼的图挂了」这类正常回复。代价是「mark 一下，谢谢楼主」漏删——它带语气、
  可能有人味，交给加强档更合适。
- **尾部语气符容忍**（`TAIL_CHARS`）：`了 ~ ! ！ 。 的 呀 啊`，即 `mark了` / `插眼~` /
  `马克!` 也命中。**只放宽一个字符**：放宽越多，误伤正常短句的概率越高。

### 3.2 AGGRESSIVE「加强去水」（第二档）

在 BASIC 全部规则之上追加：

| 序 | 规则 | 判据 | 原因文案 |
|---|---|---|---|
| 1 | 纯笑声 | 整条只由 `哈 嘿 嘻 呵 ~` 构成 | 纯笑声 |
| 2 | 简短闲聊 | 长度 ≤ 12 且**包含**词表任一项 | 简短闲聊 |

简短闲聊词表（`SMALL_TALK_TOKENS`，包含匹配，但受长度上限约束）：

```text
谢谢分享  感谢分享  多谢分享  谢谢楼主  感谢楼主  谢谢  多谢  感谢
辛苦了  支持  支持一下  好帖  好贴  好文  厉害  牛  牛逼  牛b
nb  太强了  强贴  哈哈哈哈  哈哈  笑死  笑死我了  呵呵
同求  求资源  求链接  求地址  同上  同问  同感  学习  学习了
受教  受教了  关注  围观  涨知识  涨姿势  有道理  确实  确实如此
同意  赞同  附议  打卡  签到  真实  有趣  有意思  第一个
```

**长度上限 12 是这里的关键约束**：它把「感谢分享」判水，但保留
「感谢分享，不过第 3 张图的参数好像写反了」这类带实质内容的回复。

> 口径澄清：整条由同一字符重复构成（如 `哈哈哈哈`）在 BASIC 档的「重复字符」就已命中；
> 加强档的「纯笑声」实际覆盖的是混用笑声字符（`哈哈嘿嘿`）与带 `~` 的写法。
> 若产品要求「BASIC 不删笑声」，必须显式调整规则顺序并同步本节（见 §10.8）。

### 3.3 阈值常量

| 常量 | 值 | 作用 |
|---|---|---|
| `PURE_DIGIT_MAX_LEN` | 10 | 「纯数字回复」的长度上限（超过视为有信息量） |
| `SMALL_TALK_MAX_LEN` | 12 | 加强档「简短闲聊」的长度上限 |
| `TAIL_CHARS` | `了~!！。的呀啊` | 标记类词表的尾部语气符容忍集（最多 1 个） |
| `LAUGH_CHARS` | `哈嘿嘻呵~` | 纯笑声字符集 |

## 4. 「信息字符」用反向白名单

判「纯标点 / 纯符号 / 纯表情」时，**只把枚举到的符号码点判为无信息，其余一律视为有信息**：

| 区段 | 内容 |
|---|---|
| 单个码点 | 零宽连接符 `U+200D`、变体选择符 `U+FE0F`、键帽组合符 `U+20E3` |
| `U+0021–002F` `U+003A–0040` `U+005B–0060` `U+007B–007E` | ASCII 标点四段 |
| `U+2000–206F` | 通用标点（— … “ ” 等） |
| `U+20A0–20CF` | 货币符号 |
| `U+2190–21FF` `U+2300–23FF` `U+2460–24FF` `U+2500–25FF` | 箭头 / 杂项技术符号 / 带圈数字 / 制表符 / 几何图形 |
| `U+2600–27BF` `U+2B00–2BFF` | 杂项符号与装饰符号（含 ☀ ★ ✓） |
| `U+3000–303F` | CJK 符号与标点（、。〈〉《》「」【】等） |
| `U+FE30–FE4F` | CJK 兼容形式 / 竖排标点 |
| `U+FF01–FF0F` `U+FF1A–FF20` `U+FF3B–FF40` `U+FF5B–FF65` | 全角标点四段 |
| `U+1F000–1FAFF` | emoji 补充平面（表情、图形、扩展 pictograph） |

- **为什么必须反向**：正向白名单（「只保留汉字 / 字母 / 数字」）会把泰文、西里尔文、
  阿拉伯文、各类扩展汉字这些没被枚举到的文字误判成纯标点，一删就是整段内容。反向的
  代价是「未知符号」被当成有信息（漏删几个纯符号楼）——对破坏性操作来说这个方向的错误
  才是可接受的。
- **区段枚举只增不减**：新增符号区段 = 更保守；收窄会引入「未枚举文字被误删」的破坏性 bug。
- ⚠️ **判定必须按 Unicode 码点**：`U+1F000–1FAFF` 在 UTF-16 里是代理对，用
  `charCodeAt` 拿到的是 `0xD83D` 这类代理项，永远落不进该区段（见 §10.1）。

## 5. 自定义规则

### 5.1 类型与语义

| 类型 | 短名 | 语义 | 校验 |
|---|---|---|---|
| `contains` | 内容包含 | 紧凑文本**包含**该关键词 | 非空；值先剥空白（比对的是紧凑文本，带空格的规则永远匹配不上） |
| `equals` | 内容完全等于 | 归一化（去空白 + 转小写）后**全等** | 非空 |
| `max-length` | 字数不超过 | 紧凑文本长度 ≤ 上限 | 十进制整数，**1–500** |

- **长度类必须带单位「字」**：类型短名与完整描述两处都要带（不写单位，用户会按字节或
  字符理解，汉字与 emoji 的计数完全不同）。
- 展示文案：`内容包含「X」` / `内容完全等于「X」` / `纯文本长度不超过 N 字`。
- 规则数据字段：`id`（列表键）、`enabled`、`type`、`value`（长度类为十进制数字字符串）。

### 5.2 编译与执行

- 编译期跳过：未启用、类型非法、值为空；`contains` 值先 `compactText`，`equals` 值先归一化，
  `max-length` 值取整且 ≥ 1。
- 执行顺序：`contains` → `equals` → `max-length`，命中即返回原因。
- **多条长度规则取最宽松的一条**：同时配 5 与 10 时，用户意图是「10 以内都算水」。
- 未启用的规则不参与判定；自定义规则不受严格等级影响。

## 6. AI 追加规则（会话级，可选）

内置词表与自定义规则都是**字符匹配**：前者只覆盖全站通用灌水词，后者要用户自己想出关键词。
而每个帖子有自己的「水法」——追更帖满屏「催更」、资源帖满屏「求个网盘」、攻略帖满屏
「学到了」。因此在确认弹窗里提供「按本帖主题生成」：让模型看一眼标题与主楼，列出这帖
特有的灌水表达。

**产品前提不变**：这是**追加**一个可选来源，不是替换本地判定。判定仍然不调模型，
AI 未配置时按钮给出与其它 AI 场景一致的配置原因，去水照常可用。

| 约束 | 要求 |
|---|---|
| 生效范围 | **只对本次任务生效，绝不落盘**（按帖主题生成的规则写进全局会在别的帖子误删） |
| 传递方式 | 由确认弹窗回传给帖子页，页内字段持有，发起任务时与持久化自定义规则**合并** |
| 重开清零 | 每次打开弹窗都清空页内字段（弹窗是新建实例，页内字段才是真源） |
| 生成中禁止开始 | 否则用户以为用了 AI 规则、实际一条没用上——比不用 AI 更糟 |
| UI 声明 | 必须明说「只用于本次去水，不会写入你的自定义规则」+ 数据会发送给所配置的 AI 服务 |
| 失败降级 | 生成失败或解析为空都不阻断去水：失败在 AI 区块内显示原因，解析为空时如实写「AI 认为这个帖子没有需要额外过滤的表达」 |

提示词全文、输出 JSON 契约、防御性解析规则与常量见
[AI_PROMPT_SPEC.md](AI_PROMPT_SPEC.md) §6；实现侧至少要保证：**AI 输出是不可信输入**，
逐条校验、坏条目只丢自己、绝不抛异常打断去水。

## 7. 判定入口契约

```text
judgeFloor(input, ruleSet) -> { water: boolean, reason: string }
  input: { content（原始 BBCode）, isOp, hasAttach, hasDiscussion }

  1. isOp || hasAttach || hasDiscussion                    → 保留（reason 为空）
  2. body = stripQuoteBlocks(content)
  3. 若 compactText(stripMarkup(body)) 为空 且 body 与原文不同
                                                          → 保留（只带引用的楼层）
  4. body 含任一 RICH_MARKERS                              → 保留
  5. BASIC 命中                                            → 判水（reason = BASIC 原因）
  6. 加强档且 AGGRESSIVE 命中                              → 判水
  7. 自定义规则命中                                        → 判水（reason = 自定义规则：…）
  8. 其余                                                  → 保留
```

- 判定必须是**纯函数、无 IO、无正则**（全字符串扫描）：上千页帖子的判定循环会跑几万次，
  正则回溯与对象分配是性能风险。
- 规则集在任务开始时**编译一次**（等级 + 规则列表 → 数组），判定循环里不再遍历规则表。
- `reason` 必须可读并落日志（诊断「为什么这层被判水」的唯一依据）。

## 8. 配置与持久化

| 项 | 键 / 字段 | 取值 | 默认 |
|---|---|---|---|
| 严格等级 | `waterFilterLevel` | 1 = 只清纯灌水，2 = 加强去水（越界自动夹取） | 1 |
| 自定义规则 | `waterFilterRules` | `{ id, enabled, type, value }[]`，保持用户录入顺序 | 空 |
| 配置版本号 | `waterFilterVersion`（AppStorage） | 等级或规则变更时 +1 | 0 |

- 配置域与判定引擎**分离**：设置域只负责读写配置，引擎只负责判定，任务服务把两者接起来。
  这样「把配置改回默认值」不可能影响判定逻辑本身。
- 规则 id 需在**同一毫秒内连点新增**也不撞键（时间戳 + 自增序号）。
- 加载时必须逐条规整：缺字段、类型非法、值非法（复用同一套校验）一律丢弃，等级夹取到
  合法区间；**不得**因为一条坏数据让整个配置域加载失败。
- 重置（退出登录 / 切号）回到默认等级与空规则。
- 版本号驱动的 UI 刷新是必需的：规则页与设置页是路由栈里**并存**的两个 Screen，
  从规则页返回时设置页不会重建，只靠 `aboutToAppear` 会停在旧值。

## 9. 抓取、重组与产出（工程约束）

### 9.1 抓取

| 约束 | 取值 / 做法 | 理由 |
|---|---|---|
| 页间节流 | ≥ 250 ms | 对 NGA 保持礼貌，避免触发风控 |
| 总页数来源 | **服务自行探测**（请求末页读 `__ROWS` / `__R__ROWS_PAGE` 换算） | 调用方手里的页数在「只看楼主」等筛选态下是筛选后的值，用它决定范围会漏抓大半个帖子 |
| 探测失败 | 回退调用方给的页数 | 不因为一次探测失败就整个任务作废 |
| 并发 | 串行逐页 | 无并发页请求 |
| 单页失败 | 只跳过该页并计数 | 上千页里偶发失败是常态，不得中断整帖 |
| 重复楼 | 按 `pid` 去重（**判水与否都要计入去重集**，见 §10.3） | 相邻页偶有重复的尾楼，去水版里同楼不能出现两次 |
| 安全阀 | 保留楼层数上限（如 8000 层）与产出字符上限 | 触顶立即停止扫描并落盘，如实说明「仅覆盖前 N 页」 |
| 黑名单 / 关键词屏蔽 | **不参与取舍**（判定时传空） | 屏蔽是阅读时的用户偏好，不该让存档内容随之变化 |

### 9.2 重组为同形状页

- 判定输入是解析后的楼层对象（有楼号 / 附件 / 楼中楼等语义字段），但**保留时把该行原始
  raw row 原样放进新页**：图片、楼中楼、热评、投票全都不动，也不会因字段裁剪丢内容。
- 合成页形状与在线响应一致，打开时统一由既有解析入口解释，**不得**为去水版另起渲染路径。
- 必须满足的字段语义：
  - 每页行数组（`__R`）：本页保留的楼层行；
  - 作者表（`__U`）：**必须按页裁剪**，只带本页楼层引用到的作者条目——不裁剪地复制到每一页，
    1000 页的存档光作者表就会膨胀到上百 MB；
  - 用户组映射（`__GROUPS`）：承载它的那一条**每页都要带上**，否则除首页外的楼层会退化成
    数字组 ID（并需为「整帖都找不到载体」准备兜底，见 §10.10）；
  - 总行数（`__ROWS`）报「全帖保留楼层总数」而非本页行数；
  - 每页行数（`__R__ROWS_PAGE`）与页码（`__PAGE`）与在线排版一致（每页 20 楼）。
- 内存策略：**不累积整页 raw**。每页解析后立即判定，只留下通过的原始行，其余（含该页的
  大作者表）当场变成垃圾。

### 9.3 产出存档

| 项 | 取值 |
|---|---|
| `archiveId` | `tid + '-w'`（原帖存档 = `tid`） |
| `derivedFrom` | `tid`（原帖存档为空串） |
| `subject` | 原帖标题 + `（去水版）` |
| 落盘 | 与离线存档同一目录、同一格式；原子写（先写临时文件再替换） |
| 列表标记 | 「去水」描边标签；与原帖存档并列，可独立打开 / 删除 |
| 重复执行 | 覆盖同 `archiveId` 的上一份 |
| 形状校验 | `archiveId` 必须是「纯数字」或「纯数字 + `-w`」，拒绝越界与非法后缀 |

- **存档的唯一键是 `archiveId`，不是 `tid`**：这是「同一主题并存两份存档」的基础。
  列表 `ForEach` 键、打开、删除、导入导出全部按 `archiveId`。
- 路由必须携带 `archiveId` 并透传到帖子页（离线读取按 `archiveId` 取档，只凭 `tid` 会永远
  打开原帖那一份）。
- 存量存档（没有 `archiveId` 字段）加载时回填为 `tid`，旧书签与旧调用点行为不变。
- 去水版**不支持再次去水**：离线存档来源下不出现去水入口（存档只含已保存页，与「全帖」
  语义不符）。

### 9.4 后台继续与进度

- 任务期间申请**数据传输型长时任务**（`backgroundModes` 需包含 `dataTransfer`，
  `ohos.permission.KEEP_BACKGROUND_RUNNING` 需已声明）；申请不到时降级为前台执行，
  **并在进度提示里如实告知「请保持应用在前台」**，不得静默降级或直接失败。
- 进度必须**跨页可见**（全局进度发布 + 常驻胶囊），因为去水可能跑几十分钟，用户一定会
  离开帖子页。胶囊需展示：阶段文案、进度条、页数与已去层数、剩余时间（估算）、取消入口。
- 系统取消 / 暂停长时任务时要如实反映（「后台任务已被系统暂停」）。
- 中断检查点：每页抓取前、节流等待后、落盘前。取消标记必须配合**任务代际**：
  仅靠布尔标记时，上一代任务的收官分支仍可能写入存档。
- 进程被杀不做断点恢复：存档只在全部完成后一次性写入，不留半成品。

## 10. 参考实现的已知缺陷（重实现必须修正）

| # | 缺陷 | 影响 | 正确做法 |
|---|---|---|---|
| 1 | 符号判定用 UTF-16 code unit（`charCodeAt`） | `U+1F000–1FAFF` 永远判不中 → 「😀😀😀」在默认档**不会被剔除**，与「纯表情判水」承诺矛盾；`isRepeatedChar` 逐 code unit 比较也判不出 emoji 重复 | 用 `codePointAt` + 按码点步进；重复字符判定同样按码点；长度规则也按码点计数 |
| 2 | 确认弹窗的页数 / 耗时估算取调用方的页数 | 「只看楼主」筛选态下严重低估（5 页 vs 实际 300 页），长帖警告与耗时提示失效（**抓取范围本身是对的**，服务会自行探测） | 弹窗展示与服务同源：先按服务口径探测（或明确标注「按整帖估算」） |
| 3 | 去重集在判水分支之后才写入 | 跨页重复的**水楼层**被重复计数 → 结果文案「去掉 N 层」虚高（存档内容不受影响） | 去重判定与写集放在判水之前 |
| 4 | 产出字符上限只按正文字符数 + 固定余量估算 | 实际保留的是整行 raw row（含附件 / 楼中楼 / 热评）→ 字符上限近似失效，真实约束只剩行数上限 | 按整行序列化长度（或抽样估算）计量，或直接下调行数上限 |
| 5 | 「已有去水版」判断函数未接线 | 重复去水会静默覆盖，用户无提示 | 入口或确认框提示「将覆盖已有的去水版」 |
| 6 | 抓取请求没有单页超时；取消只在响应返回后生效 | 弱网 / 断流时「取消」形同虚设，全局进度胶囊会长时间停在「正在取消…」 | 单页请求加超时；取消时立即停止推进并收掉进度层 |
| 7 | 隐私声明只写了「不写入自定义规则」 | 用户不知道标题与主楼正文会被发送给第三方 AI 服务 | 在 AI 规则区块明确写出外发内容与去向 |
| 8 | 整条同字符重复在默认档就命中 | 与「纯笑声属于加强档」的产品口径不一致 | 明确产品口径并让文档与实现一致 |
| 9 | 未配对 `[quote` 按「丢弃到文末」处理 | 作者自写正文被一并丢弃 → 紧凑文本变短，反而**更容易**命中 `max-length` 类规则 | 保留该异常分支，但要在文档与验收里固定它的语义；或改为「只丢弃到下一个可识别边界」 |
| 10 | 用户组载体找不到时无兜底 | 非首页楼层可能退化成数字组 ID | 找不到载体时显式构造或明确降级并在验收中覆盖 |
| 11 | 非楼层结构行不判定直接保留 | 可能让去水版页数膨胀或渲染异常 | 只保留能映射到楼层对象、或明确属于页结构的行 |
| 12 | 任务回调无页面级代际 / 销毁保护 | 页面销毁后仍会弹 Toast、读已失效的帖子 ID | 与全帖总结同模式：页内代际 + 销毁取消 |
| 13 | 判定完全无自动化测试 | 词表、引用剥离、码点判定这类纯逻辑最容易回归，也最好测 | 判定引擎、AI 规则解析、存档键迁移三处必须补单元测试（纯函数、无 IO） |

## 11. 验收清单

判定（可用真实帖子或构造数据逐条核对）：

- 「mark」「插眼」「马克」「留名」「绑定」等单层回复在默认档被剔除。
- 「mark 一下，谢谢楼主」在默认档**保留**；「谢谢分享」「哈哈哈哈」在加强档被剔除。
- 含 `顶` 但语义正常的回复（「顶楼的图挂了」）**不被剔除**。
- 纯 emoji（`😀😀😀`）、`。。。`、`!!!!`、`12345` 在默认档被剔除。
- 带图片附件 / 带楼中楼 / 主楼的楼层**永不被剔除**。
- 只引用、自己没写字的楼层**保留**；「引用一整楼 + 一个 mark」的水楼层**照删**。
- 引用不计入长度：配一条「字数不超过 = 20」，录一层「引用 200 字长文 + `顶一下`」仍被剔除。
- 自定义规则三种类型各命中一次；未启用的规则不影响结果；两条长度规则取宽松值。
- 各条判定的 `reason` 与文档文案一致（诊断与验收共用一套措辞）。

入口与产出：

- 「更多」菜单里的入口可见；离线存档来源下不出现该项。
- 确认框内能看到**产出位置**（完整路径）、当前等级与生效规则条数、页数与耗时估算（标注
  为估算）。
- 未登录 / 帖子未加载完成 / 已有任务在跑 / AI 规则正在生成 分别给出提示，均不进入抓取。
- 完成后「保存的帖子」里同时出现原帖存档与带「去水」标签的去水版，两条都能独立打开、
  独立删除；删掉去水版不影响原帖；对同一帖重复去水仍只有一条。
- 去水版打开后版式与在线一致：图片、楼中楼、用户组名、楼层号正常，可「在线模式打开」。

长帖与中断：

- 抓取期间全局进度胶囊显示页数与剩余时间，**离开帖子页后进度仍在**。
- 点「取消」后任务及时停止、不生成存档；返回键退出页面不产生残留写入。
- 退到后台再回前台，任务继续（长时任务申请成功时）；失败时文案说明保持前台。
- 抓取过程中断网：失败页被跳过并计数，结果文案写明「N 页未取到」。

AI 规则（需先配置 AI；未配置时降级为「提示原因且去水照常可用」）：

- 生成期间点「开始」被拦并提示；生成结束后清单可见且与规则描述文案一致（长度类带「字」）。
- **AI 规则不落盘**：关掉再打开弹窗清单回到空；设置里的自定义规则列表没有多出条目。
- 生成中途取消不留无人接收的回调：不报错、不弹「生成失败」。

## 12. 维护规则

- 改内置词表（标记类 / 短闲聊 / 各阈值）必须同步更新第 3 节，并复核「整条等值 vs 包含
  匹配」的取舍理由是否仍成立。
- 改符号区段枚举：方向**只增不减**（新增 = 更保守）；**不得**为了删得更狠而收窄。
- 改自定义规则类型或校验区间：同步第 5 节、设置页编辑器文案（长度类的单位「字」两处都要带）。
- 改引用剥离边界：复核第 2.2 节的「宁可少判一层水」取舍，并确认「先剥引用、再剥标记」
  的顺序未被颠倒。
- 改 AI 规则的输出格式：三处必须同时改——默认 system prompt、解析器、
  [AI_PROMPT_SPEC.md](AI_PROMPT_SPEC.md) §6。
- **不得**把 AI 规则写进持久化配置：那是按帖主题生成的会话级数据，落盘就会在别的帖子误删。
- 改存档键规则（`archiveId` 形状 / 后缀）：必须同时改存储层、路由、列表与导入导出，
  并验证存量存档仍可读。
- 改安全阀常量：同步第 9.1 节与结果文案。
- 改合成页字段：核对解析入口的读取口径（尤其作者表 / 用户组 / 总行数），并用一份真实去水版
  在离线模式下逐页翻完验证。
- 改确认框必读信息：**产出位置不可删**——用户只有在这一处能知道去水版存到了哪。
- **不得**把去水判定改成调用模型：那会让结果不可预期、消耗额度，并破坏「AI 未配置也能用」
  这条产品前提。AI 只作为**追加**的可选规则来源。
