# AI 场景与提示词契约

本工程所有 AI 功能共用**一条调用通道**，`scenario`（场景）是这条链路上唯一的扩展键：
它决定注入哪个 system prompt。本文档收录各场景的**提示词全文**、注入数据格式、
输出契约，以及多服务商 / 工具 / Agent 的实现边界。

```text
入口（页面 / 服务）
  → 组装注入数据（service/，纯取数 + 拼文本）
  → chatCompleteWithActiveAiStream（唯一 AI 通道）
      → AiChatClient 按 profile.protocol 路由
          ├─ Responses API        （DeepSeek 官方、OpenAI 兼容 /responses）
          └─ Chat Completions     （第三方 OpenAI 兼容服务商）
      → AiAgentRunner 多步工具循环
          ├─ 模型返回 function_call
          ├─ 客户端经搜索服务商适配器执行 web_search / web_fetch（当前 DeepSeek 官方）
          └─ 结果以 function_call_output / tool 消息回传，继续生成
  → 流式增量渲染（对话类场景） 或 取最终文本 + 解析（结构化输出场景）
```

> **文档定位**：提示词与注入数据格式属于**产品资产**——实现可以重写，契约应当保留。
> 重实现时逐字沿用本文档的提示词，除非有意变更产品口径（那必须同时改默认提示词、
> 注入字段说明与维护规则）。

> **2026-10 更新**：场景已升级为「AI 任务」（`AiAgentPreset`），工具从「每个 AI 配置的私有开关」
> 改为**全局工具设置**，并新增 NGA 站内只读工具集。本文档中关于 `profile.toolsEnabled` 等
> 配置内工具字段的描述已废弃，最新契约见 `docs/AI_AGENT_REDESIGN.md`。
> 下文两套内置提示词仍然有效：它们是两个内置任务的默认 system prompt。

## 1. 场景总览

| 场景 ID | 名称 | 入口 | 数据来源 | 输出形态 | 联网工具 |
|---|---|---|---|---|---|
| `post_summary` | 单楼层总结 | 楼层动作栏 AI 图标 | 该楼层正文（已缓存） | 对话流式 | 允许 |
| `user_analysis` | 用户画像分析 | 用户页 | 用户活跃数据 + 帖子 / 回复片段 | 对话流式 | 允许 |

场景注册必须**三处同时配**（缺一处就会静默少一个环节）：

| 注册表 | 内容 | 漏配表现 |
|---|---|---|
| 场景元数据 | 设置页卡片的标题与描述 | 设置页读到 `undefined` |
| 默认 system prompt | 该场景的默认提示词 | system prompt 静默丢失，AI 表现为「不听话」 |
| 注入字段说明 | 设置页只读展示「本次会注入哪些数据」 | 预览列表遍历 `undefined` |

## 2. 通用约束

- **system prompt 来源**：按场景从设置里读取（用户可覆盖默认值）。读取结果为**空串**时
  必须按「未配置」处理并给出可读原因（提示用户去 AI 配置检查），**不得**带着空 prompt 发起请求。
- **注入数据边界**：只注入渲染后的**纯文本**（标题、楼层正文、统计数字）。
  **不得**注入 Cookie、会话令牌、用户 ID 之外的账号凭据、图片二进制；黑名单用户的楼层
  按设置跳过时**只计数不注入正文**。
- **截断必须显式标注**：注入数据被截断时要在文本里留下可见标记（如
  `……（后续内容已省略）`、`……（本层正文已截断）`）；覆盖范围与截断原因必须写进提示词，
  并要求模型不要推断未纳入的部分。**不得**在截断后仍声称「已包含全部内容」。
- **联网工具**：工具开关已全局化（`AiToolSettings`，见 `docs/AI_AGENT_REDESIGN.md`），
  不再存在 `profile.toolsEnabled` / `profile.enableWebSearch` / `profile.enableWebFetch`。
  需要「不联网」的场景应在任务层面不勾选 `web_search` / `web_fetch`，或在全局工具页关闭。
- **流式 vs 一次性**：对话类场景展示增量；结构化输出场景不展示增量，只取最终文本后解析。
- **取消**：所有调用必须带取消令牌，页面销毁或用户点「停止」时取消。
- **失败降级**：AI 失败不得阻断其宿主功能（如去水在 AI 规则生成失败时照常可用），
  失败原因要在对应 UI 区块内如实显示。
- **不可信输入**：模型输出必须按不可信输入处理——工具参数要防御性解析，结构化输出要逐条校验，
  坏条目只丢自己，绝不抛异常打断主流程。
- **工具结果由客户端生成**：`web_search` / `web_fetch` 的返回结构是 DeepSeek 官方固定格式，
  不依赖对话服务商返回什么；自定义服务商只需支持 OpenAI 标准的 function calling 即可接入。

## 3. 场景 `post_summary`：单楼层总结

**system prompt（默认值，逐字）**：

```text
你是一个专业的帖子内容分析助手。请根据用户提供的帖子正文内容进行深度总结归纳。

分析要点：
1. 核心观点：提取帖子的主要论点和立场
2. 关键信息：列出重要的事实、数据或论据
3. 逻辑脉络：梳理帖子的行文结构和论证逻辑
4. 一句话总结：用精炼的语言概括帖子的核心内容
```

**注入字段**（设置页展示用）：

| 标签 | 示例 |
|---|---|
| 帖子标题 | 原标题文本 |
| 楼层 | `#1` |
| 作者 | 用户名 |
| 正文内容 | 帖子的纯文本内容 |

**用法**：楼层动作栏的 AI 图标 → 跳 AI 对话页，注入上述数据作为初始提示词，
结果以流式对话呈现，可继续追问。

## 4. 场景 `user_analysis`：用户画像分析

**system prompt（默认值，逐字）**：

```text
你是一个论坛用户行为分析专家。请根据用户提供的论坛活跃数据，分析并总结以下内容：

1. 用户画像：推断该用户的身份、兴趣领域、在论坛中的角色
2. 政治光谱：根据其讨论话题和立场倾向，判断其政治倾向
3. 整体点评：以辛辣尖锐的语言风格对其用户画像进行一句话锐评
```

**注入字段**：

| 标签 | 示例 |
|---|---|
| 用户名 | 用户昵称 |
| UID | `12345678` |
| 帖子数 | `12 个帖子` |
| 回复数 | `45 条回复` |
| 活跃版面 | 水区、游戏区、数码区等 |
| 发帖时段分布 | 凌晨 3 帖 / 上午 8 帖 / 下午 15 帖 / 晚上 19 帖 |
| 发表的帖子 | 前若干条帖子标题列表 |
| 回复内容 | 前若干条回复片段 |

## 5. 配置模型

### 5.1 对话配置（`AiProviderProfile`）

| 字段 | 说明 |
|---|---|
| `presetId` | `deepseek` 官方 / `custom` 自定义；决定表单预填与默认协议 |
| `endpoint` | 对话端点基础地址（可含 `/v1`，也可直接写完整协议路径） |
| `apiKey` | 对话密钥 |
| `modelName` | 模型标识；DeepSeek 可点「拉取模型」从 `GET /models` 选择 |
| `protocol` | `responses`（DeepSeek 默认）/ `chat_completions`（第三方通用） |
| `temperature` | 0–2，默认 0.7 |
| `toolsEnabled` / `enableWebSearch` / `enableWebFetch` | 客户端工具开关 |
| `maxAgentSteps` | 单次提问内工具循环上限（1–1000，默认 6） |

> 旧版本遗留的 `searchProvider` / `toolsEndpoint` / `toolsApiKey` 字段仍保留在模型里，
> **只用于一次性迁移**（见 5.2），新配置不再写入，执行期也不读取。

### 5.2 搜索配置（`AiSearchProfile`）

搜索服务是**独立配置列表 + 激活一套**，与对话配置互不影响：

| 字段 | 说明 |
|---|---|
| `id` / `name` | 标识与用户命名的方案名 |
| `providerKind` | 搜索服务商标识（当前仅 `deepseek`，注册表负责回退） |
| `endpoint` | 搜索服务端点（默认 `https://api.deepseek.com`） |
| `apiKey` | 搜索服务密钥（与对话密钥独立） |

**迁移规则**：首次加载旧版本设置时，从激活的对话配置生成一套搜索配置：
`toolsApiKey` 优先，缺失且对话端点为 DeepSeek 时复用对话 `apiKey`；
端点取 `toolsEndpoint`，服务商取 `searchProvider`，全部缺失则用 DeepSeek 官方默认值。
迁移后旧字段不再参与执行。

**工具可用性**：对话配置的 `toolsEnabled` + 对应工具开关，加上激活搜索配置的
`isAvailable()`（当前即密钥非空），两者都满足才会把工具声明给模型。

**端点派生**（`AiEndpoint.ets`）：
`buildChatUrl` 按协议补 `/responses` 或 `/chat/completions`；用户已填完整路径时原样使用。
`buildModelsUrl` 先剥离协议后缀再拼 `/models`。
`buildToolsUrl` 识别用户填写的完整工具路径（`.../tools/search` 或 `.../tools/fetch`），
按目标工具重建，避免 search 与 fetch 落到同一个 URL。

## 6. 工具与 Agent 契约

**搜索服务商可插拔**：模型侧永远只有 `web_search` / `web_fetch` 两个工具；
执行后端由**激活的搜索配置**决定，经 `SearchProviderRegistry` 分发到
`AiSearchProvider` 适配器。当前只注册 **DeepSeek 官方**一种，新增服务商只需实现
适配器并注册一行，工具定义、Agent 循环、聊天页都不需要改。

| 工具 | 参数 | 当前执行后端 | 返回给模型的内容 |
|---|---|---|---|
| `web_search` | `query`（必填）、`count`（1–10，默认 5） | `POST {搜索配置.endpoint}/v1/tools/search` | 编号列表：标题 + URL + 发布时间 + 摘要 |
| `web_fetch` | `url`（必填，http/https） | `POST {搜索配置.endpoint}/v1/tools/fetch` | 页面标题 + URL + Markdown 正文（超 12000 字截断并标注） |

**服务商可用性**：由适配器 `isAvailable(搜索配置)` 判断（DeepSeek 需要搜索密钥）。
工具层先看对话侧开关，再看搜索配置凭据；任一不满足就不把工具声明给模型。

**Agent 循环**（`AiAgentRunner.ets`）：

1. 未达到轮数上限的请求携带当前可用的工具定义与 `tool_choice: auto`；
2. 模型返回 `function_call` 时，客户端顺序执行并记录 `AiToolInvocation`（含耗时、结果数、来源）；
3. 工具结果按协议回传：Responses 用 `function_call_output` item，Chat Completions 用 `tool` 消息；
4. 工具轮数达到 `maxAgentSteps` 后，再发一次**不带工具**的收尾请求，并在 UI 标注「已达工具调用轮数上限」；
5. 任一步取消立即中断，不再执行后续工具。

**UI 契约**：每次工具开始 / 完成 / 失败都通过 `ToolInvocationCallback` 推送完整时间线快照；
聊天页展示「工具名 + 参数摘要 + 状态 + 结果数」，气泡底部展示去重后的引用来源（最多 4 条）。

## 7. Markdown 渲染契约

AI 回答按 Markdown 渲染，客户端支持：

| 结构 | 语法 | 渲染 |
|---|---|---|
| 标题 | `#` – `######` | 分级字号 / 字重 |
| 段落 | 连续文本行 | 保留软换行 |
| 粗体 / 斜体 / 删除线 | `**` / `*` / `~~` | 内联 Span，可嵌套 |
| 行内代码 | `` `code` `` | 等宽 + 背景 |
| 围栏代码块 | ` ```lang ` | 等宽横向滚动 + 语言标签 |
| 列表 | `-` / `1.` | 项目符号 / 序号，支持一层缩进子列表 |
| 任务列表 | `- [ ]` / `- [x]` | ☐ / ☑，完成项灰化 |
| 引用 | `>` | 左边框 + 斜体 |
| 分隔线 | `---` | Divider |
| 链接 | `[text](url)`、裸 `https://…` | 主色下划线，点击走系统浏览器 |
| 图片 | `![alt](url)` | 块级图片（限高 320vp）；内联图片降级为「[图片] alt」 |
| 表格 | `\| a \| b \|` + 分隔行 | 表头加粗，按 `:---` / `:---:` / `---:` 对齐 |

**流式渲染策略**：稳定前缀按行增量解析并进入 AST；未完结行（含未闭合代码块）用轻量
Text 渲染并附加游标。表格在流式期间按普通行展示，最终气泡完整解析后转为表格。
**未闭合标记按普通文本处理**（尾段贪婪解析除外），由下一次全量重解析自动修正。

## 8. 重实现注意事项（已知边界）

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 对话历史只保留纯文本 | 追问「刚才搜到的第二条」时模型看不到原始工具结果 | 需要时把 `AiAgentResult` 的完整 items 落盘；当前接受该降级 |
| 2 | 表格在流式期间按普通行显示 | 生成过程中观感与最终结果不同 | 需要时让流式拆分器把整张表留到闭合后再提交 |
| 3 | 自定义服务商的 `/models` 不一定存在 | 拉取失败 | UI 已提示「手动填写模型名称」，不阻断保存 |
| 4 | 部分服务商思考模式忽略 `temperature` | 调参无效 | 设置页已注明；不要客户端伪造采样 |
| 5 | 整帖正文外发无二次确认 | 点一次菜单即把大量正文发往所配置服务商 | 需要时增加首次使用提示 |
| 6 | 服务商预设里的默认模型名会随厂商下线而变化 | 新建配置后首次调用即失败 | 定期核对线上模型名；失败信息要能被用户看懂 |
| 7 | 日志只记录状态码与固定文案，不记录响应体 | 服务端原始错误难以定位 | 需要排查时临时开启脱敏日志，不要在默认路径落 body |

## 9. 维护规则

- 改任一场景的默认提示词：必须同步更新本节对应区块，并复核注入字段说明与设置页预览。
- 新增 AI 场景：三张注册表（元数据 / 默认 system prompt / 注入字段）缺一不可，
  并同步 §1 的场景表与本文档正文。
- 新增工具：实现 `AiToolAdapter` 并在 `ToolRegistry` 注册一行；工具结果必须给出
  模型可读的纯文本与 UI 可用的摘要 / 来源。
- 新增搜索服务商：实现 `AiSearchProvider`（search / fetch / isAvailable），在
  `SearchProviderRegistry` 注册一行，并在设置页选择器里自动出现（无需改 UI 代码）。
- **不得**为某个场景另开第二条对话 HTTP 调用路径：协议分支只存在于 `AiChatClient`。
  （工具执行属于独立能力，经搜索服务商适配器执行，不属于对话通道。）
- **不得**在结构化输出场景打开联网工具。
- 注入数据若有新增字段：核对「只注入纯文本、不含凭据与图片」这条边界。
